# tzo-anim web player

Play [TZO](https://github.com/jorisvddonk/tzo) animation programs in the browser.

This is the web counterpart of the texture/animation VM from
[tzo-c](https://github.com/jorisvddonk/tzo-c)'s `anim.c`: it loads a TZO program
(`.json`), provides the `loadImage` / `beginDraw` / `endDraw` / `drawFrame`
foreign functions, renders the frames on a canvas and drives the animation with
the `anim_anim_<i>_index` / `_active` / `_yy_direction` context state.

Live: **https://jorisvddonk.github.io/tzo-anim-web/**

## Format specification

The animation extension is documented in
[`public/docs/anim-format.md`](public/docs/anim-format.md) (served at
`/docs/anim-format.md`): foreign functions, texture/hotspot model, the
`anim_anim_*` context state, program structure, timing, animation types and a
reference trace you can validate a new implementation against. It deliberately
covers only the animation additions — the VM itself is the
[core TZO specification](https://github.com/jorisvddonk/tzo).

## How it works

* The TZO virtual machine is the **official [`tzo` npm package](https://www.npmjs.com/package/tzo)**
  (a normal dependency in `package.json`), bundled by Vite — no copy of the VM
  lives in this repository.
* Loading is a two-phase process, like `anim.c`'s two `run()` calls:
  1. the program is executed with a recording `loadImage` to find out which
     content files it needs (the init phase ends in a `pause`),
  2. those images are decoded and the program is run for real, so `loadImage`
     can hand out texture indices synchronously.
* Rendering mirrors `anim.c`: textures keep their hotspot offsets,
  `drawFrame(n)` blits texture `n` at `(-hotspotX, -hotspotY)`, the frame buffer
  is persistent (so a background drawn once stays on screen) and `endDraw()`
  presents it. Unlike `anim.c`, alpha is kept so sprites are transparent.

## Loading a project

| How | What |
|---|---|
| **Open .zip…** | a `.zip` containing the program `.json` plus the content files (any folder layout) |
| **Open folder…** | a folder with the program and its images (File System Access API, with a `webkitdirectory` fallback) |
| **Open program…** | a `.json` program, then optionally the folder with its content files |
| Drag & drop | a `.zip`, a folder, or a program + images |

If an archive or folder contains several programs you get to pick one. Images
are looked up by path first and by file name second, so the UQM-style paths in
exported programs (`base/comm/yehat/yehat-000.png`) work as long as the files
are somewhere in the project.

The bundled example (`✨ Load example`, or `?example=chmmr`) is the chmmr comm
screen animation exported from
[UQMAnimationTool](https://github.com/jorisvddonk/uqmanimationtool)'s TZO
exporter.

## Controls

* `Space` play/pause, `→` single tick, `R` restart
* speed slider (1–120 ticks per second, default 30 like `anim.c`)
* zoom: fit or 1×–4×
* the sidebar shows the program facts, the live `anim_anim_*` animation state
  and every context key

## Development

```bash
npm install
npm run dev            # http://localhost:5173
npm test               # node unit tests (content loading, renderer, player)
npm run build          # production build in dist/
```

### Browser smoke test

```bash
npm run dev &
node tests/browser-check.mjs http://localhost:5173/ --screenshots=/tmp/shots
```

It drives headless Chrome over the DevTools Protocol: loads the example,
checks that frames are drawn and ticking, exercises pause/step/restart and
loads `tests/fixtures/sample.zip`.

### Test fixtures

`tests/fixtures/` is generated by `node tools/make-fixtures.mjs` (tiny PNGs
encoded by hand, a hand-written TZO program and the same files zipped up).

## Notes

* The reference TZO VM implements the `{` opcode by looking for the function
  named `openBrace` in the program list. Bundlers rename functions
  (`openBrace` → `openBrace2`), which breaks every `if` block, so the player
  restores those function names after loading a program
  (`ensureBraceFunctionNames` in `src/player.js`, covered by a test).
* `anim.c`'s `MAX_TEXTURES` is 128; the player has no such limit.

## Deployment

`.github/workflows/pages.yml` runs the tests, builds the app and publishes
`dist/` to GitHub Pages on every push to `main`. Set *Pages → Build and
deployment → Source* to **GitHub Actions**.
